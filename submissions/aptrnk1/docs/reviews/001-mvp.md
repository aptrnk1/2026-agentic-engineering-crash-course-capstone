# Review: `aptrnk1` branch (agentlog CLI) against AGENTS.md

## Summary

I read the C# code in `src/` and `tests/`, the hooks, and the commit history. The Core library follows the architecture rules. It has no `File`, `Console` or `DateTime.Now` calls, `TimeProvider` is used for "today", data types are records, and there is no static mutable state. The CLI is thin and returns exit code 2 for a missing file, and a test checks that.

`dotnet test -warnaserror` passed 41 tests: 26 in Core and 15 in Cli, with 0 failed. One caveat: the `exit=0` I saw came from `tail` in the pipe, not from `dotnet test`.

The biggest problem is outside the C# code. The last commit's change to the SessionStart hook crashes every time it runs, but `docs/evidence.md` says it was checked and works. There is also one counting bug in Core, an unstable `--format json` shape, and a few gaps in test coverage.

## Bugs

1. **`.claude/hooks/session-context.mjs:7-9`: the hook throws a `ReferenceError` on every session start.** Commit `6e4ab05` removed `import { join } from "node:path"` and `const root = ...`, but lines 7, 9, 12 and 17 still use `join` and `root`. `readdirSync` is used on line 9 but never imported. Line 7 runs at the top level, outside the `try`, so the error ends the process before anything is printed. The agent gets no "today" summary at all, which is the same symptom the commit was meant to fix.
   - **Fix:** a human should restore `import { join } from "node:path"`, add `readdirSync` to the `node:fs` import, and restore `const root = process.env.CLAUDE_PROJECT_DIR || process.cwd();`. AGENTS.md forbids agents from editing `.claude/**`.

2. **`docs/evidence.md` (added in `6e4ab05`): the evidence points to a commit that doesn't exist.** The table rows say "Fix: 2f3743b" and "коміт `2f3743b` фіксу hook". `git log --all` has no `2f3743b`. The fix that was actually committed is `6e4ab05`, and it is broken (see #1). The quoted agent answer must have come from a working-tree version that was never committed. This breaks the "evidence, not claims" rule.
   - **Fix:** after fixing #1, re-run the restart check against the committed hook and cite the real commit hash.

3. **`src/AgentLog.Core/Aggregator.cs:138`: an executed line with no `exit` is counted as failed.** `IsFailed` is `executed.Exit != Success`, and `null != Success` is `true`. Example: a hand-trimmed log, an older hook, or any non-Pre event the hook writes as `"event":"unknown"` (log-action.mjs:24) with no `exit` adds 1 to `failed` and appears in `agentlog failed` with exit `-`. No test covers a Post line without `exit`.
   - **Fix:** `executed.Exit is { } x && x != Success`, plus a test with `PostToolUse` and no `exit`, expecting `Failed == 0`. Also consider counting only `PostToolUse` and `PostToolUseFailure` as executed, rather than "anything not Pre" (line 131).

## Risks

4. **`src/AgentLog.Core/ReportFormatter.cs:16`: the `--format json` shape depends on the data.** `JsonIgnoreCondition.WhenWritingNull` drops keys:
   - On an empty log, or one where `--since` filters out every line, the summary JSON has no `first` and no `last`.
   - In `blocked` and `failed`, entries lose `id`, `mode`, `path`, `cmd`, `exit` and `ms` whenever they are null.

   A consumer that does `.first` or `.exit` gets "missing property" instead of `null`. The rules require stable JSON output.
   - **Fix:** always write the keys with `null` (drop `WhenWritingNull`, or apply it only to `path`, `cmd`, `pattern` and `url`). Add an e2e test for `--format json` on an empty file.

5. **`src/AgentLog.Core/Aggregator.cs:135-136`: an action that is still running is reported as "blocked".** Running `agentlog` from inside a session logs a Pre line, and the Post line only arrives after the command finishes. The fixture's single "blocked" line (`cat -n .agent-log/actions.jsonl | cut ...`, fixture line 19) is exactly this case. The tests treat it as a real block. The `summary --since today` that feeds the SessionStart context will always show at least one false block if the hook runs while a tool is executing.
   - **Fix:** document this limit, or label Pre lines without a Post as "pending" when they are the newest lines of their session or within N seconds of the last line. At minimum, rename the test fixture's case so it doesn't read as proof of correct behaviour.

6. **`src/AgentLog.Core/Aggregator.cs:69-70` vs `:107`: `summary` and `files` count files differently.** In `summary`, `UniqueFiles` counts paths from Pre lines too, including blocked or denied proposals. `files` counts only executed lines. Example: a denied `Write .env` shows up as "files: 1" in the summary, but `agentlog files` doesn't list it.
   - **Fix:** count only non-Pre lines in `UniqueFiles` (matching `Files`), or document the difference. Add a test with a blocked Write to a path.

7. **`src/AgentLog.Core/LogEntry.cs:16`: one odd field drops the whole line.** If `ms` is a non-integer (e.g. `12.5`) or `exit` is an unknown string (e.g. `"timeout"`), JSON parsing fails and the line is skipped. All of its counts are lost, not just that field. The hook passes `duration_ms` through unchanged (log-action.mjs:63), and the converter rejects any `exit` string that isn't one of the two known values (ExitStatusJsonConverter.cs:23).
   - **Fix:** make the converter return `ExitKind.Error` (or a new `Unknown` kind) for unknown strings, and read `ms` as a number then round it. Add tests for both cases.

8. **`src/AgentLog.Cli/CliApp.cs:61-77`: exit code priority, and unreadable files.**
   - `--since` is validated before the file check, so `agentlog no/such/file --since soon` returns 1, not 2.
   - A path that is a directory gets "No log at …" (exit 2), which is misleading but acceptable.
   - A file that exists but can't be read (permissions) makes `File.ReadLines` throw. System.CommandLine's default handler then prints a stack trace and returns 1.
   - **Fix:** check the file first, decide whether "missing file" should beat "bad args" or the other way round, and add a test either way. Catch `IOException` and `UnauthorizedAccessException` and return a clear message with its own exit code.

## Nits

9. **`tests/AgentLog.Core.Tests/UnitTest1.cs`, `tests/AgentLog.Cli.Tests/UnitTest1.cs`: empty placeholder tests.** They always pass and inflate the quoted count (41 includes 2 no-ops). Delete them.

10. **Edge cases with no tests** (the checklist in my brief asks for these):
    - **Empty file:** `Summarize([])` and the CLI on a 0-byte file should give `0 executed … - .. -` plus a header-only table. Not tested.
    - **Windows paths:** there is no test that `path` values with backslashes or drive letters (e.g. `D:\repo\x.cs` when the hook didn't relativize them) are grouped in `files` and the Markdown table. `Files` groups with `StringComparer.Ordinal` (Aggregator.cs:108), so `D:/x` and `d:/x` would count as two files.
    - **`--since` boundary:** no test has a line whose `ts` equals `since` exactly, so changing `>=` to `>` in LogFilter.cs:12 would not fail any test.
    - **Unknown `exit` string:** the parser has no test for something like `"exit":"weird"`.

11. **`src/AgentLog.Core/AgentLog.Core.csproj:5`: `ImplicitUsings` brings in `global using System.IO` for Core.** Nothing in Core uses it today, but nothing would stop someone adding `File.ReadLines` there. Consider `<Using Remove="System.IO" />` in the Core csproj, or an architecture test that Core doesn't reference `System.IO.File` or `System.Console`.

12. **Commit hygiene:**
    - `6e4ab05 Fix agentlog.dll search` is not a Conventional Commit (it should be `fix(hooks): ...`). It also mixes a hook fix with evidence docs, and it was a bug fix with no failing test first.
    - `c3360ee` combines filters with three new reports, so it is not "one logical change per commit".

13. **Test projects pull in packages beyond the allowed list.** AGENTS.md allows "System.CommandLine, xunit". The test projects also reference `coverlet.collector`, `Microsoft.NET.Test.Sdk` and `xunit.runner.visualstudio`. These come from the template and are needed to run tests, but under the rules they should be explicitly approved, or AGENTS.md should list them.

14. **`.claude/skills/vercel-react-best-practices/**` (about 3,800 lines).** This is a React/Next.js skill in a .NET CLI repo. It adds context noise and has nothing to do with the task. Consider removing it from this submission.

15. **`src/AgentLog.Core/LogLineParser.cs:27`: `ts` of `0001-01-01T00:00:00Z` is treated as missing.** That's harmless, but a nullable `DateTimeOffset?` `Ts` checked for `null` would say what's meant.

## What I checked

- AGENTS.md architecture rules (Core purity, TimeProvider, records, no static mutable state, thin CLI), package and file boundaries, and commit conventions.
- Log-format edge cases: malformed or blank lines, missing `id`, `exit` as int or string, missing `exit`, unknown `exit`, non-integer `ms`, Windows paths, empty file, and in-flight Pre lines.
- Tests: whether each behaviour has a test, and whether the assertions would fail if the code were wrong (gaps are listed in #10).
- CLI contract: exit 2 for a missing file, exit 1 for a bad `--since`, and JSON stability.
- `dotnet test -warnaserror`: 41 passed, 0 failed.

## Verdict

**Request changes.** The C# Core and CLI are mostly sound and well tested. Before merging:
- Fix the crashing SessionStart hook (#1) and correct the evidence that points to a nonexistent commit (#2). Both are required by the "evidence, not claims" rule.
- Fix the null-`exit` counting bug (#3).
- Make the `--format json` shape stable (#4).

The other items can go in follow-ups.
